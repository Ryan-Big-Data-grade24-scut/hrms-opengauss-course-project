### 1.2 架构原则

1. **数据优先**：先有完整数据，再谈分析和ML。所有seed数据必须覆盖85%+员工。
2. **权限不可绕过**：所有端点必须经过`_require_auth`或`_require_permission`，无公开数据露点。
3. **后端能力全消费**：后端已实现的API前端必须全部接入（当前仅接入23%）。
4. **字段名统一**：DDL以代码实现的列名为准，更新设计文档以匹配代码。
5. **组件共享**：所有页面共享ErrorBanner/Spinner/Pagination/Skeleton/TabBar组件，消除内联实现。

## 2. 数据设计（字段全覆盖方案）

### 2.1 表重构原则

所有表遵循以下命名规范（与Service SQL实际使用一致，更新DDL设计文档以匹配）：

```
主键格式: {table_name}_id  (如 employee_id, department_id)
名称字段: full_name / department_name / position_name / skill_name
状态字段: employment_status / employment_type
时间字段: created_at / updated_at  (统一后缀)
JOIN字段: 显式FK名 (如 manager_employee_id, position_id)
```

### 2.2 employee 表（24列 → 28列）

保持现有24列不变（已与Service SQL一致），新增4列：

| 列名 | 类型 | 说明 |
|------|------|------|
| emergency_contact | varchar(50) | 紧急联系人姓名 |
| emergency_phone | varchar(20) | 紧急联系人电话 |
| personal_email | varchar(100) | 个人邮箱（区别于公司邮箱） |
| last_review_rating | smallint | 最近一次绩效等级（物化列，由sync刷新） |

**替代物化列方案**：不删除现有`attendance_absent_count`/`attendance_late_count`/`avg_performance_score`三列，但创建视图进行统一维护：

```sql
CREATE VIEW v_employee_analytics_features AS
SELECT
    e.employee_id,
    COALESCE(a.absent_count, 0) AS attendance_absent_count,
    COALESCE(a.late_count, 0) AS attendance_late_count,
    COALESCE(p.avg_score, 0) AS avg_performance_score
FROM employee e
LEFT JOIN (
    SELECT employee_id,
        COUNT(*) FILTER (WHERE status = 'absent') AS absent_count,
        COUNT(*) FILTER (WHERE status = 'late') AS late_count
    FROM attendance_record GROUP BY employee_id
) a ON e.employee_id = a.employee_id
LEFT JOIN (
    SELECT employee_id, AVG(score)::numeric(5,2) AS avg_score
    FROM performance_review GROUP BY employee_id
) p ON e.employee_id = p.employee_id;
```

## 3. 办事大厅设计（Skill从部门→岗位→技能需求选择）

### 3.1 核心设计变更

当前：技能变更页面从全局`/api/skills`加载技能列表直接选择（自由文本input做select）。

目标：**四步选择流程**：选部门 → 看到该部门的岗位 → 选岗位 → 看到该岗位要求的技能 → 选要添加的技能。

### 3.2 四步前端组件

```
SkillChangeForm
  ├── Step 1: 部门选择器 (DepartmentSelector)
  │     └── 从 /api/departments 加载部门列表，<select> 单选
  │
  ├── Step 2: 岗位选择器 (PositionSelector)
  │     └── 根据选定部门调用 /api/positions?department_id={deptId}
  │     └── 展示该部门的岗位列表，<select> 单选
  │
  ├── Step 3: 技能需求展示 (RequiredSkillsView)
  │     └── 从 /api/skills/required?position_id={posId} 加载
  │     └── 展示该岗位要求的所有技能及目标等级
  │     └── 卡片/列表形式：技能名 | 目标等级 | 当前员工已有(打勾标记)
  │
```

### 6.3 考勤数据生成逻辑（V11核心）

```sql
-- 为每个员工生成过去90个工作日的考勤记录
-- 高风险员工: 30%迟到 + 15%缺勤
-- 中风险员工: 10%迟到 + 5%缺勤
-- 低风险员工: 5%迟到 + 2%缺勤
-- 使用generate_series + 加权随机
WITH emp_risk_level AS (
    SELECT e.employee_id,
        CASE WHEN es.engagement_score < 60 THEN 'high'
             WHEN es.engagement_score < 75 THEN 'medium'
             ELSE 'low'
        END AS risk_level
    FROM employee e
    JOIN ...
),
-- 为每个员工生成日期序列
dates AS (
    SELECT e.employee_id, d::date AS record_date,
        CASE WHEN e.risk_level = 'high' THEN
            CASE WHEN random() < 0.3 THEN 'late'
                 WHEN random() < 0.15 THEN 'absent'
                 ELSE 'present'
            END
        WHEN e.risk_level = 'medium' THEN ...
        ELSE ...
        END AS status
    FROM emp_risk_level e
    CROSS JOIN generate_series('2025-03-01'::date, '2025-05-30'::date, '1 day'::interval) d
    WHERE EXTRACT(DOW FROM d) NOT IN (0, 6)  -- 排除周末
)
INSERT INTO attendance_record (employee_id, record_date, clock_in, clock_out, status, created_at)
SELECT employee_id, record_date,
    CASE status
        WHEN 'absent' THEN NULL
        WHEN 'late' THEN record_date + '09:15'::time + (random()*45||' minutes')::interval
        ELSE record_date + '08:30'::time + (random()*30||' minutes')::interval
    END,
    CASE status
        WHEN 'absent' THEN NULL
        ELSE record_date + '18:00'::time + (random()*30||' minutes')::interval
    END,
    status, NOW()
FROM dates;
```

### 6.4 绩效数据生成逻辑（V12核心）

```sql

         WHEN e.engagement_score < 80 THEN 65 + (e.engagement_score * 0.2)::int

    END,

         WHEN e.engagement_score < 75 THEN '符合预期，有提升空间'
```
