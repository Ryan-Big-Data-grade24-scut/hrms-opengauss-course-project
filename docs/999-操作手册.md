## 2. 后端测试指令（curl）

所有 curl 命令基于后端 `http://127.0.0.1:18080`。

### 2.1 登录

```bash
# 登录（所有账号密码相同）
TOKEN=$(curl -s http://127.0.0.1:18080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"123456"}' | python -c "import sys,json;print(json.load(sys.stdin)['data']['token'])")
echo "TOKEN=$TOKEN"
```

### 2.2 组织人员

```bash
# 组织树
curl -s http://127.0.0.1:18080/api/v2/org-people/tree \
  -H "Authorization: Bearer $TOKEN" | python -m json.tool

# 按部门查员工（将 {dept_id} 替换为 1-4）
curl -s "http://127.0.0.1:18080/api/org-people/employees?department_id={dept_id}" \
  -H "Authorization: Bearer $TOKEN" | python -m json.tool

# 按部门+岗位筛选
curl -s "http://127.0.0.1:18080/api/org-people/employees?department_id=1&position_id=4" \
  -H "Authorization: Bearer $TOKEN" | python -m json.tool

# 搜索员工
curl -s "http://127.0.0.1:18080/api/org-people/search?q=Alex" \
  -H "Authorization: Bearer $TOKEN" | python -m json.tool

# Bundle API（员工详情，将 {emp_id} 替换为 503-562）
curl -s "http://127.0.0.1:18080/api/org/employee/{emp_id}" \
  -H "Authorization: Bearer $TOKEN" | python -m json.tool
```

### 2.4 审批流

```bash
# 提交技能新增审批
curl -s http://127.0.0.1:18080/api/approval-requests \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"operation_type":"SKILL_ADD","target_id":509,
       "payload":{"action":"add","skill_id":1,"proficiency":3}}' | python -m json.tool

# 提交请假审批
curl -s http://127.0.0.1:18080/api/approval-requests \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"operation_type":"LEAVE_REQUEST","target_id":509,
       "payload":{"leave_type_id":1,"start_date":"2026-06-10","end_date":"2026-06-12","reason":"年假"}}' | python -m json.tool

# 提交考勤补卡
curl -s http://127.0.0.1:18080/api/approval-requests \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"operation_type":"ATTENDANCE_CORRECTION","target_id":509,
       "payload":{"date":"2026-06-03","period":"full","reason":"忘打卡"}}' | python -m json.tool

# 提交信息修改
curl -s http://127.0.0.1:18080/api/approval-requests \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"operation_type":"PROFILE_UPDATE","target_id":509,
       "payload":{"fields":{"phone":"13800138000"},"reason":"更新手机号"}}' | python -m json.tool

# 查看待审批（用审批人的 TOKEN）
HR_TOKEN=$(curl -s ... -d '{"username":"vp_eng","password":"123456"}' | python -c "import sys,json;print(json.load(sys.stdin)['data']['token'])")
curl -s http://127.0.0.1:18080/api/v2/approval-requests/pending \
  -H "Authorization: Bearer $HR_TOKEN" | python -m json.tool

# 批准（将 {id} 替换为实际的 request_id）
curl -s -X PUT http://127.0.0.1:18080/api/v2/approval-requests/{id}/approve \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $HR_TOKEN" \
  -d '{"comment":"批准"}' | python -m json.tool

# 驳回
curl -s -X PUT http://127.0.0.1:18080/api/v2/approval-requests/{id}/reject \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $HR_TOKEN" \
  -d '{"comment":"需补充说明"}' | python -m json.tool

# 撤回（仅申请人可操作）
curl -s -X PUT http://127.0.0.1:18080/api/v2/approval-requests/{id}/recall \
  -H "Authorization: Bearer $TOKEN" | python -m json.tool

# 我的申请
curl -s http://127.0.0.1:18080/api/v2/approval-requests/my \
  -H "Authorization: Bearer $TOKEN" | python -m json.tool

# 我处理的
curl -s http://127.0.0.1:18080/api/v2/approval-requests/done \
  -H "Authorization: Bearer $TOKEN" | python -m json.tool

# 审批详情
curl -s http://127.0.0.1:18080/api/v2/approval-requests/{id}/logs \
  -H "Authorization: Bearer $TOKEN" | python -m json.tool
```

## 3. 前端操作步骤

### 3.1 登录

浏览器打开 `http://127.0.0.1:5173`，输入任一账号 + 密码 `123456`。

**账号权限差异**：

| 账号 | 可见菜单 |
|------|---------|
| admin / ceo | 全部菜单 |
| vp_eng / eng_mgr / hr_mgr | 办事大厅、组织人员、技能管理、数据分析 |
| employee | 办事大厅、组织人员、技能管理 |

### 3.2 办事大厅

#### 发起申请（4 种类型）

| 类型 | 表单字段 | 审批链 |
|------|---------|--------|
| 技能变更 | 操作类型（新增/修改/删除）+ 技能选择 + 熟练度 + 说明 | 直属上级 → HR |
| 请假 | 请假类型 + 日期范围 + 说明 | 直属上级 → HR |
| 考勤补卡 | 补卡日期 + 时段 + 时间 + 说明 | 直属上级 → HR |
| 信息修改 | 电话/邮箱 + 说明 | HR |

#### 待审批（审批人视角）

- 技能变更/请假 → 直属上级先批，HR 后批
- 信息修改 → HR 直接批
- 批准/驳回需填写意见

#### 我的申请（申请人视角）

- 可撤回（PENDING 状态时）
- 查看审批链进度

### 3.3 组织人员

| 功能 | 操作 |
|------|------|
| 部门树 | 左侧树形结构，点击展开子部门 |
| 岗位筛选 | 部门选中后显示岗位标签，点击筛选 |
| 搜索 | 按姓名/岗位模糊搜索 |
| Profile | 点击员工查看详细信息、联系方式、技能、履历 |

### 3.4 技能管理

| 功能 | 操作 |
|------|------|
| 选择员工 | 顶部下拉框选择 |
| 添加技能 | 点击 Add Skill → 选择 All Skills 或 Required → 选技能 + 熟练度 → 提交审批 |
| 修改等级 | 鼠标悬停技能项 → 点击编辑图标 → 滑块调级 → 提交审批 |
| 删除技能 | 鼠标悬停 → 点击 X → 自动提交审批 |
| AI 推断 | 从履历技术栈自动匹配技能（提交审批） |
| 履历管理 | 新增/编辑/删除工作履历 |

### 3.5 数据分析（5 标签页）

| 标签 | 内容 |
|------|------|
| 离职风险 | 风险列表（分页/排序/筛选）+ 风险因子标签 |
| 技能缺口 | 组织级覆盖率 + 部门下钻 |
| 部门矩阵 | 按部门分组的技能类别热力图 |
| 出勤绩效 | 考勤汇总 + 绩效汇总 |
| 综合健康 | 部门健康分 + 重点人员列表 |

### 5.5 常见问题

| 问题 | 原因 | 解决 |
|------|------|------|
| 提交审批报 400 | 后端未启动或审批链配置缺失 | `python test_all_v2.py` 检查 |
| 审批通过后数据没变 | `_execute_payload` 未匹配 action_type | 确认使用 SKILL_ADD 而非 SKILL_CHANGE |
| 前端白屏 | Vite 热更新断连 | 刷新浏览器或重启 Vite |
| 端口占用 | 僵尸进程未清理 | `taskkill /F /IM python.exe` |
